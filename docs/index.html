01 / the cast

roles/

Seven roles, one runtime. Each spawn is a real child session with its own model, brief, and file write-set. Read it like a running order.

01 orchestrator deepseek-v4.1-flash Plans the board, spawns workers, reviews only escalations, closes with evidence.
02 worker deepseek-v4.1-flash Owns a task and a write-set. Claims files, edits, tests, and reports back.
03 tester deepseek-v4.1-flash Runs the commands, checks the acceptance criteria, writes the proof.
04 scout flash #low Read-only reconnaissance. Maps the repo before anyone touches it.
05 reviewer flash #high Reads the diff against the plan. Approves, or sends it back with reasons.
06 planner flash #high Turns a vague goal into tasks with disjoint write-sets and dependencies.
07 integrator flash #high Runs the full gate, resolves the seams, and prepares the final summary.

03 / the hard part

no-lost-updates/

Parallel agents are easy to demo and hard to trust. Three layers keep the workspace consistent, and a fourth keeps the bill honest.

fig. 01 — control plane over shared state
partition
Plan-time write-sets. Overlapping open tasks are rejected unless a dependency orders them.
leases
Claim before edit. File and directory leases conflict correctly, and expire on a TTL.
hashes
Stale writes fail. If the file changed since the last read, the edit is refused and must re-read.
budget
Cost is the guard. Warn, then pause. Member, depth, and concurrency caps are separate.
same-file edits serialize by design · worktrees are next

07 / before you ask

questions/

The honest answers, including the parts that are still missing.

installDo I need OpenCode Go?+

No. Any tool-capable provider works. DeepSeek V4.1 Flash on OpenCode Go is only the default because it is cheap and fast at this task shape. Set models.orchestrator to "inherit" to follow whatever model you picked with /models.

safetyCan two workers edit the same file?+

Not concurrently. The board rejects overlapping write-sets at plan time, leases serialize whatever still collides, and the content-hash guard refuses a write when the file changed underneath the worker.

costWhat stops a runaway swarm?+

A cost budget with warn and pause thresholds, plus member, depth, concurrency, and message-rate caps. /swarm-stop interrupts everything immediately. The budget is tracked per swarm, not per session.

autonomyDoes it run forever on its own?+

No. It is goal-driven, not a daemon. It stops when the board is done, when you stop it, when the budget is hit, or when a limit is exceeded. It will not invent new goals.

limitsIs it a sandbox?+

No, and you should not treat it as one. Workers run with the permissions OpenCode gives them. Destructive shell commands are blocked or escalated, but interpreters and repo content are still dangerous. Point it at repositories you trust.

roadmapWhat is still missing?+

Worktree isolation and a merge queue, a TUI dashboard for live state, an npm package, and richer plan validation. The current model is a shared workspace with leases, which is safe but serializes same-file edits. See the roadmap.
