Built for real parallel work

Not a chat room of agents. A task board, file leases, peer messaging, and a deterministic supervisor.

01

Plan-time write-sets

Every task declares the files it may touch. Overlapping open tasks are rejected unless one depends on the other.

02

File leases + hashes

Workers claim files before editing. A content-hash check rejects writes when another agent changed the file first.

03

Peer messaging

Workers ask each other questions directly. The orchestrator sees digests, not every message.

04

Low-friction reviews

Routine spawns and file claims are automatic. Only sub-subagents, directory leases, thresholds, and budget warnings reach the orchestrator.

05

Supervised recovery

Stale locks, idle workers, failures, retries, budgets, and completion are handled by a background supervisor.

06

Goal-driven autonomy

Give it a goal. It plans, spawns, coordinates, verifies, and closes the swarm without asking you to approve each step.

How it works

Six steps from one goal to a verified result.

01 planThe orchestrator creates tasks with write-sets, acceptance criteria, dependencies, and a size.
02 validateThe board rejects overlapping write-sets unless a dependency orders the tasks.
03 spawnWorkers get child sessions, focused briefs, roles, and file leases.
04 finishThe orchestrator reviews, verifies, integrates, and closes with a summary and test evidence.

Simple install

Clone it, point OpenCode at it, and start a swarm from any chat.

terminal
# 1. clone and install
git clone https://github.com/DumDuky/opencode-swarm.git
cd opencode-swarm
bun install

Requires OpenCode 2.x, Bun 1.4+, and a tool-capable model. DeepSeek V4.1 Flash on OpenCode Go is the default.

use it
# 2. from any chat
/swarm Add a health endpoint with tests

Or call swarm_start directly to keep the current agent. /swarm-status shows the live board.

~/.config/opencode/opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    { "package": "/absolute/path/to/opencode-swarm", "options": {} }
  ],
  "instructions": [
    "/absolute/path/to/opencode-swarm/docs/SWARM.md"
  ]
}
Single project? Put the same plugins entry in the project's opencode.json. For V1, use the loader in examples/local-plugin/swarm.ts.

After editing config, run opencode reload. If a TUI chat was already open, restart the TUI once.

Parallel without the chaos

The swarm is autonomous, but not unbounded.

No lost updates

Plan-time partitioning, file leases, and content-hash checks. Same-file edits serialize by design.

Only real decisions

Routine work is automatic. The orchestrator reviews sub-subagents, directory leases, thresholds, and budget warnings.

Stops when it should

Hard budget, member/depth/concurrency caps, destructive-command blocks, and /swarm-stop.
